# UI - Plan

## Goal Capsule

- **Objective:** A freelancer can set up the model, build a package, see every finding with its evidence, decide on each one, and export and check reviewed copies in the browser, and the screens always show honest coverage and where the model runs.
- **Owner:** Teammate D (Stream 4).
- **Product authority:** `sentineldesk-overview.md` sections 5, 7, 16, 23. The HTTP API and types come from `lib/contract/` (Stream 1). Coordination rules are in `docs/plans/2026-10-09-1558-docs-team-split-plan.md`.
- **Open blockers:** None for setup. Real data needs the Stream 1 stub routes (hour 3).

---

## Product Contract

### Summary

Stream 4 builds all screens in overview section 7 with shadcn/ui: Settings, Packages list, New package, Scan progress, Review (three columns with viewer and manual box tool), Preview, and Export with the verification report. It calls the API through a typed client built on the contract types, and it builds against the stub routes and fixtures until the real server is ready.

### Key Decisions

- **Build against stub routes, not local mocks.** Stream 1 stub routes return contract fixtures from hour 3. The UI uses the same HTTP calls from the start, so integration needs no rewrite. Governs R2.
- **Polling for job progress.** Matches the server decision in the team-split plan. Governs R10.
- **shadcn components only.** Install with the shadcn CLI; do not recreate them (AGENTS.md). Governs R1.

### How This Work Fits Together

This plan covers Stream 4 only.

- Depends on Stream 1 for the HTTP API, types, and fixtures.
- Can proceed independently of Stream 2 and Stream 3; their output reaches the UI only through Stream 1 routes.

### Requirements

**Setup (hour 0-3)**

- R1. Run shadcn init and install the components from overview section 7 (Button, Card, Badge, Dialog, Tabs, Table, Input, Select, Checkbox, Progress, ScrollArea, Separator, Tooltip, Sonner, Resizable, Alert) with the CLI.
- R2. `lib/client/` is a typed API client that uses the contract types and covers every route in the contract route table.
- R3. The app shell has navigation and loads no remote fonts or scripts at runtime. The current `next/font/google` use in `app/layout.tsx` is replaced with a local or system font.
- R4. The UI follows the React Effects rules in AGENTS.md. Data fetching is in the parent; polling uses an Effect with cleanup that ignores stale responses.

**Settings (M1)**

- R5. Settings has base URL, API key status (masked, set from env only), text model, vision model, and timeout. "Test connection" shows the model list, JSON test result, and latency.
- R6. The locality badge shows Local (green), LAN (blue, with host), or Remote (red, with host), and a mode preview.

**Packages (M2, M3)**

- R7. The Packages list shows name, recipient, profile, date, status, and open findings count, with a "Delete package" action.
- R8. New package has name, a recipient select (or create a recipient with a profile) with an allowed / needs decision / remove summary, protected terms as chips, a multi-file drop zone, and a file list with type and size. Profiles can be edited (M3).
- R9. When the badge is Remote, starting a scan shows the dialog "File text and images will be sent to `<host>`."

**Scan progress (M10, M17)**

- R10. Scan progress shows the line "N of M files scanned · X findings to review · Y files could not be read · Mode: <mode> (<locality>)" and per-file status. It polls the job route.
- R11. When the mode is Rules only (at start or after a model failure), a clear banner says that AI analysis did not run.

**Review (M11, M12, M13, M14)**

- R12. Review has three columns: file list with counts and status icons (failed, no AI, unsupported); a viewer (text with highlighted spans, image with boxes); a findings list filterable by category, method, and status.
- R13. Each finding card shows what, where, why, how detected, the suggested action, the actions redact / keep / keep and remember / not an issue / exclude file, and a "Find related" button. "Allowed for this recipient" is shown when it applies. "Exclude file" is a file decision, not a finding decision.
- R14. The manual box tool lets the user draw, move, and delete a box on an image. `image-whole` findings ask the user to draw a box.
- R15. Find related shows exact matches and "possible related (AI suggestion)" as separate groups, with one action for a full group.
- R16. The package banner shows inconsistent-redaction warnings.
- R17. Keyboard shortcuts: next / previous finding, redact, keep.
- R18. A file with any coverage problem never shows a green or done state without a visible marker.

**Preview, export, verification (M15, M16)**

- R19. Preview shows original and reviewed copy side by side for each file.
- R20. Export asks for confirmation when warnings are open, shows progress, then the verification report: files exported, files excluded, redactions per category, open findings after re-scan, files not analyzed by AI, unsupported files, locality, model names, and the zip download.
- R21. The result text is "Reviewed. No open detected findings." or the list of open findings with links back to Review. The UI never uses the words "safe", "clean", or "no sensitive information".

### Key Flows

- F1. Demo path
  - **Trigger:** user opens the app at `http://127.0.0.1:3000`.
  - **Steps:** Settings (Local badge) → New package (recipient, protected term, drop 6 files) → Scan progress → Review (decide, find related, fix warning) → Preview → Export → Verification report → Download.
  - **Covered by:** R5-R21.

### Acceptance Examples

- AE1. **Covers R18.**
  - **Given:** `broken.png` failed and `spec.md` has `aiAnalysis: "skipped-no-model"`.
  - **When:** the Review file list renders.
  - **Then:** `broken.png` shows a failed icon with the reason, and `spec.md` shows a "no AI" marker, not a green state.
- AE2. **Covers R11.**
  - **Given:** a scan in Full mode.
  - **When:** the job reports a switch to Rules only.
  - **Then:** the banner appears without a page reload.
- AE3. **Covers R14.**
  - **Given:** a vision finding with `image-whole` evidence.
  - **When:** the user selects it.
  - **Then:** the viewer prompts the user to draw a box, and the box becomes the finding's region.

### Success Criteria

- Every screen works against stub routes by hour 10 and against the real server at Integration 1 (hour 12).
- The built app makes no network calls except to `127.0.0.1` (check in browser dev tools with the network off).

### Scope Boundaries

- No server logic, detection, or LLM calls (Streams 1-3).
- Evaluation page (S1) and bulk actions (S3) are stretch.
- No mobile layout work beyond basic responsiveness.

### Dependencies / Assumptions

- Stream 1 stub routes are on `main` by hour 3. Until then, the UI uses contract fixture objects directly.
- Upload sends one file per request, in sequence (Stream 1 plan KTD4).
- A package can come back with an interrupted flag after a server restart; the UI shows it and offers a new scan (Stream 1 plan KTD5).
